## The Evolving Role of Programmers Due to the Advancement AI

<hr>

#### 前提として起こる事
「ソフトウェア開発の仕組みが大きく変革する」

#### メリット
- 開発速度の飛躍的な向上
- 人材不足の解消

#### デメリット

### プログラマーとしての仕事の変化
AIを駆使出来る部分は最大限活用し、人間の手を加える必要がある部分の業務に変化していくと思われる。大雑把にリストアップするのなら
- 開発対象となる言語の知識コーディングAIそのものを扱える知識、また出力されたコードが最低限どんな事をしているか理解出来、修正、改修が出来る能力。
  - 例えば「こう直して欲しい」と言われる（いわゆる仕様変更）にAIが対応出来なかったら？また出力したコードが正常に動かなかったら？
- <strong>ドメイン知識（領域知識・業務知識）</strong>
  - 要はクライアントがどんな業種で、どんなソフトウェアを求めているか。例えば銀行だったり小売り店だったり等。
- 上流工程への移行
  - 要件定義や外部設計/内部設計、セキュリティ面やUI,UXの導線引き
- AIが出力したコードのデバッグ、妥当性チェック、QA(クオリティコントロール)

### 今後、プログラマーの需要は減少するか

結論から言うと、分からない。と言うのも最近のAIの発展が異常に早いため。ただ、少なくとも仕様書を元に実装するだけ（コードを書いて機能を実現するだけ）の下流工程プログラマは減るかもしれない。かもしれない、と言うのは現状コーディングAIにもコストがあり、規模に応じて比例する。その採算が取れなければ、と言う話になるだろう。

但し、上述した様に、ソフトウェア開発においては人間のアタマで考える必要がある部分は今尚多分に存在する。

#### 以下、Geminiより引用

> AIの普及により、プログラマの仕事は「コードを大量に書く作業」から「AIを駆使してシステム全体を設計・管理する作業」へと、その役割が大きくシフトしています。仕事自体がなくなるわけではありませんが、求められるスキルや業務内容は以下のように変化しています。

> 仕事の変化と影響定型的なコーディングの自動化:
>> 画面の量産や、よくあるAPI連携、簡単なテストコード作成などはAIが瞬時にこなすため、作業者としてのジュニアプログラマの需要は減少傾向にあります。

> 開発の裾野の拡大: 以前は予算や人手不足で見送られていた中小企業のシステム化や、個人でのツール開発が手軽にできるようになり、世の中全体のソフトウェア開発量自体は増えています。「プログラミング」から「ソフトウェアエンジニアリング」へ: コードを書くこと自体の価値が下がった分、要件定義、システム設計、セキュリティ担保、AIが生成したコードの妥当性評価（デバッグ）といった上流・品質管理の重要性が高まっています。

> AI時代に求められるプログラマ像
>> AIのオーケストレーション（使いこなし）: GitHub CopilotなどのAIエージェントを指示役（プロンプト）として使いこなし、開発スピードを何倍にも高められる生産性。アーキテクチャ設計・プロダクト思考: 「何を作るべきか」という課題を発見し、ビジネスの目的に合わせて全体像を設計できる能力。  高度な問題解決力とデバッグ力: AIが出力した複雑なコードのバグや脆弱性を見抜き、責任を持ってシステムを安定稼働させる力。単に「指示されたコードをミスなく書く」だけの人材はAIに代替されますが、AIを相棒にして複雑な課題を解決できるエンジニアの価値は、むしろ高まっています。
